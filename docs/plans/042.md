# Plan 042 - Positive-vs-Negative Drink Evaluation Gate

## Goal

Strengthen drink recommendation release evidence so reviewed positive beverage
candidates must score higher than reviewed negative counterexamples for every
offline fixture.

## Problem

The drink evaluator already measured `positive_score_above_negative_rate`, but
the release gate allowed `0.9` and the report did not expose detailed failure
payloads. That left a production-quality gap: the top five results could still
look acceptable while the underlying score function failed to separate
fixture-approved matches from explicit negative examples.

## Scope

- Add fixture-level `positive_score_above_negative` and
  `positive_negative_margin`.
- Add aggregate failure payloads for fixtures where positives do not score
  above negatives.
- Add minimum and average positive-negative margin metrics.
- Print the positive-vs-negative rate in the evaluation CLI output.
- Raise the release gate threshold from `0.9` to `1.0`.
- Add focused tests for success and intentional failure cases.
- Update release-gate documentation.

## Non-Goals

- No scoring formula change.
- No fixture rewrite.
- No DB schema change.
- No API/proto change.
- No chatbot or Flutter change.

## Acceptance Criteria

- [x] Current reviewed fixtures keep `positive_score_above_negative_rate = 1.0`.
- [x] Current reviewed fixtures have no positive-vs-negative failure payloads.
- [x] Evaluation report includes minimum and average positive-negative margins.
- [x] Intentionally inverted positive/negative fixture reports a failure.
- [x] Release gate requires `--min-positive-above-negative-rate 1.0`.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

Rollback is limited to evaluation reporting, threshold, tests, and docs. Remove
the new margin/failure metrics and restore the release gate threshold to `0.9`
only if product review accepts weaker offline recommendation evidence.
