# Plan 025 - Active Category Evaluation Coverage Gate

## Goal

Improve production confidence in drink recommendations by ensuring every active
beverage catalog category is covered by offline recommendation evaluation
fixtures.

## Problem

The existing drink evaluation gate checks top-k hit rate, negative violations,
reason-code coverage, and average category/style match rate. Those metrics can
still pass even if a newly active beverage category has no evaluation fixture.
That creates a blind spot: a category could regress without the release gate
noticing.

## Scope

- Add active catalog category coverage metrics to the drink evaluation report.
- Add CLI thresholds for active category fixture coverage.
- Require full active category coverage in the release gate.
- Add tests proving current fixture coverage and missing-category detection.

## Non-Goals

- No scoring weight change.
- No catalog data change.
- No survey mapper change.
- No model training.
- No Flutter, gateway, chatbot, or map-service implementation.

## New Metrics

```text
active_catalog_categories
fixture_expected_categories
fixture_category_counts
covered_active_categories
missing_fixture_categories
unexpected_fixture_categories
active_category_fixture_coverage
minimum_fixtures_per_active_category
```

## Release Gate Threshold

```text
fixture_count >= 24
top_k_hit_rate >= 0.95
active_category_fixture_coverage >= 1.0
minimum_fixtures_per_active_category >= 2
```

This is intentionally conservative. It requires multiple fixtures for every
active category before deployment. Later, higher standards can require
scenario-specific coverage for budget, beginner, expert, and flavor clusters.

## Acceptance Criteria

- [x] evaluation report includes active category coverage metrics.
- [x] CLI can fail on insufficient category coverage.
- [x] release gate requires full active category coverage.
- [x] release gate requires at least two fixtures per active category.
- [x] low-coverage categories have additional fixtures.
- [x] tests prove current coverage is complete.
- [x] tests prove missing fixture categories are detected.
- [ ] focused checks pass.
- [ ] full release gate passes.

## Rollback

Rollback is code/documentation only. Remove the coverage metrics and release
gate thresholds. Existing ranking and evaluation fixtures are unchanged.
