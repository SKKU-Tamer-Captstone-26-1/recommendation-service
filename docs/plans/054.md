# Plan 054 - Deployed Venue Place Type Smoke Gate

## Goal

Make the newly added venue `place_types` request contract verifiable against a
deployed recommendation-service revision.

## Problem

Plan 053 added request-time place-type filtering for selected-beverage venue
recommendations. Local tests prove the service behavior, but production
readiness also needs deployed smoke evidence. Without deployed smoke coverage,
Flutter, app-gateway-service, and chatbot-service could believe the field is
available while the deployed revision still ignores or rejects it.

## Scope

- Add `RECOMMENDATION_SMOKE_VENUE_PLACE_TYPES` to deployed recommendation smoke.
- Send the configured values through `GetVenueRecommendations.place_types`.
- Validate returned snapshot `place_type` values when venue contract validation
  is enabled.
- Support friendly alias expectations for `store`, `bar`, and `outdoor`.
- Add `RECOMMENDATION_SMOKE_EXPECT_VENUE_PLACE_TYPES` for stricter expected
  response filters.
- Update tests and operations docs.

## Non-Goals

- No map-service implementation.
- No canonical place taxonomy change.
- No DB schema change.
- No route provider change.
- No Flutter, app-gateway, chatbot, or LLM code change.

## Boundary Decision

This smoke only calls deployed service APIs. It does not read or write
map-service storage and does not turn recommendation-service into a canonical
place owner.

## Acceptance Criteria

- [x] Deployed recommendation smoke can send `place_types`.
- [x] Venue contract validation checks response `place_type` values against the
  request alias.
- [x] Smoke can enforce stricter expected response place types.
- [x] Unit tests cover successful `store -> liquor_shop` validation.
- [x] Unit tests fail when `store` returns an unrelated bar response.
- [x] Operations docs document the new smoke env vars.
- [x] Focused tests pass.
- [x] Release gate passes.

## Rollback

Remove the smoke env parsing, request field population, validation helper,
tests, and docs. The runtime API from Plan 053 remains valid without this smoke
gate, but deployed evidence would be weaker.
