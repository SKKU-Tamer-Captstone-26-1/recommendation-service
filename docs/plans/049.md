# Plan 049 - Deployed Venue Distance Contract Smoke

## Goal

Strengthen production evidence for location-aware recommendations by validating
that deployed `GetVenueRecommendations` returns venue cards with auditable
distance metadata.

## Problem

The deployed recommendation smoke could call `GetVenueRecommendations` when a
selected beverage id was configured, but it only recorded the result count. That
was not enough to prove that Flutter or chatbot-service can safely display
distance-aware venue recommendations.

A deployed response could omit rank, place identifiers, reason codes,
explanations, score metadata, or route-vs-straight-line metadata and the smoke
would still pass.

## Scope

- Add opt-in venue response contract validation to deployed smoke.
- Verify sequential ranks, result ids, place ids, names, place types, finite
  distances, finite scores, reason codes, explanations, score breakdown
  metadata, and `metadata.source`.
- Verify `metadata.source.distance_strategy`, `distance_source`,
  `distance_confidence`, `is_route_distance`, straight-line distance, and
  route distance fields.
- Add an opt-in route-distance requirement for staging fixtures that must prove
  map-service route integration is active.
- Add focused tests.
- Document the environment variables.

## Non-Goals

- No scoring formula change.
- No DB schema change.
- No API/proto change.
- No Flutter, gateway, chatbot, map-service, or LLM implementation.
- No canonical place, inventory, price, or route ownership change.
- No model training.

## Environment

```text
RECOMMENDATION_SMOKE_SELECTED_BEVERAGE_ID=<safe-beverage-uuid>
RECOMMENDATION_SMOKE_EXPECT_VENUE_RESULTS=true
RECOMMENDATION_SMOKE_VALIDATE_VENUE_CONTRACT=true
RECOMMENDATION_SMOKE_EXPECT_ROUTE_DISTANCE=true
```

`RECOMMENDATION_SMOKE_VALIDATE_VENUE_CONTRACT` is opt-in so older staging
deployments can still run reachability smoke. Production-like evidence should
enable it after safe fixture data exists.

`RECOMMENDATION_SMOKE_EXPECT_ROUTE_DISTANCE` should be enabled only when the
chosen selected beverage and coordinates are known to return at least one route
distance from map-service. Otherwise straight-line fallback remains valid but
must be described as approximate.

## Acceptance Criteria

- [x] Deployed smoke can validate venue card contract.
- [x] Deployed smoke can validate distance metadata.
- [x] Deployed smoke can require at least one route-distance result.
- [x] Missing route-distance evidence fails when route expectation is enabled.
- [x] Focused tests pass.
- [x] Release gate passes.

## Rollback

Rollback is code/documentation only. Remove the opt-in venue validation helper,
tests, and docs. Existing reachability smoke behavior remains unchanged when
validation env vars are unset.
