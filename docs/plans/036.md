# Plan 036 - Route Distance Request Observability

## Goal

Make venue recommendation request logs explain how much of a response used
future map-service route distance versus straight-line fallback distance.

This supports production operation after map-service route distance is deployed.

## Problem

Plan 033 and Plan 034 added route distance provider interfaces and runtime
wiring. The request log already stores the selected distance strategy and source
set, but it does not answer these operational questions:

```text
How many returned results used route distance?
How many fell back to straight-line distance?
What is the route coverage for this response?
Did an empty response incorrectly look like mixed distance?
```

Without counts, operators cannot distinguish a healthy partial fallback from a
route provider outage by reading `recommendation_requests.request_context_json`.

## Scope

- Add request-level distance result counts.
- Add route coverage ratio.
- Add strategy/source count maps.
- Report `no_distance_results` when no venue result is returned.
- Update focused venue recommendation tests.
- Update map read-model documentation.

## Non-Goals

- No map-service client implementation.
- No route API contract change.
- No recommendation scoring change.
- No Flutter change.
- No database schema change.
- No cross-service DB read.

## Request Context Fields

Venue recommendation request logs include:

```text
distance_result_count
route_distance_result_count
straight_line_distance_result_count
fallback_distance_result_count
unknown_distance_result_count
distance_route_coverage
distance_strategy_counts
distance_source_counts
```

These fields are stored in `RecommendationRequest.request_context_json` only.
Per-result source metadata remains the authoritative display source for each
venue card.

## Acceptance Criteria

- [x] All-route response logs route coverage `1.0`.
- [x] Partial route fallback response logs route coverage `0.5` in the fixture.
- [x] Empty venue response logs `distance_strategy = no_distance_results`.
- [x] Request logs include strategy/source count maps.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

Rollback is code/documentation only. Revert request-context additions and tests.
Existing recommendation result rows remain valid because per-result metadata is
unchanged.
