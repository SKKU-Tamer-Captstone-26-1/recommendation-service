# Plan 020 - Category-Aware Beverage Scoring V3

## Goal

Improve drink recommendation precision by making beverage taste similarity
category-aware while preserving deterministic, versioned, rollback-safe scoring.

## Problem

`scoring_v2` added budget-aware beverage scoring, but taste similarity still used
plain `cosine_taste_v1` across all 16 taste dimensions. That treats every
dimension equally for every category, even though categories emphasize different
signals:

- whiskey: smoke, oak, body, sweetness
- wine: acidity, tannin, fruit, body
- beer: bitterness, carbonation, roast
- cocktail: acidity, sweetness, herbal notes, spirit-forward intensity

This is too generic for production-quality drink recommendations.

## Scope

- Add `scoring_v3` as a new scoring config version.
- Keep `scoring_v1` and `scoring_v2` as rollback targets.
- Add `category_weighted_similarity_v1` for beverage similarity.
- Store category dimension weights in `scoring_configs.reason_code_rules_json`.
- Expose similarity strategy and weights in model features.
- Make release gate evaluate `scoring_v3`.

## Non-Goals

- No ML training.
- No new vector schema.
- No Qdrant behavior change.
- No direct survey/map DB access.
- No chatbot or Flutter ranking logic.

## Scoring Behavior

For `scoring_v1` and `scoring_v2`:

```text
taste_similarity = cosine_taste_v1(profile_vector, beverage_vector)
```

For `scoring_v3`:

```text
taste_similarity = weighted_cosine_taste_v1(
  profile_vector,
  beverage_vector,
  category_dimension_weights[beverage.category]
)
```

The canonical vector values do not change. Only the scoring config changes how
similarity is interpreted.

## Acceptance Criteria

- [x] focused tests pass.

## Rollback

Rollback serving behavior with:

```text
ACTIVE_SCORING_CONFIG=scoring_v2
```

Database rollback deprecates the `scoring_v3` rows:

```bash
alembic downgrade 0006_beverage_images
```
