# Plan 029 - Beverage Follow-up Diversity Evaluation Gate

## Goal

Make drink follow-up recommendations safer for production by requiring offline
evaluation evidence that `DIFFERENT` and `ADJACENT` beverage diversity modes
return deterministic non-repeat follow-up candidates after excluding the rank-one
standard recommendation.

## Problem

Plan 013 added API-level exclusion and diversity controls. Unit tests prove the
controls work on tiny handcrafted candidate sets, but release evidence should
also prove the reviewed seed catalog and current active scoring config can
support real follow-up behavior.

The user-facing failure this prevents:

```text
User: "다른 술 추천해줘"
Service: returns the same top drink again, or returns a near-duplicate when a
        better different-style follow-up exists.
```

## Scope

- Add offline evaluation metrics for `different` and `adjacent` follow-up modes.
- Evaluate follow-up behavior against the same seed catalog and fixture profiles
  used for drink precision checks.
- Exclude the standard rank-one beverage before follow-up selection.
- Require `different` mode to return a non-repeated candidate with changed style
  or category when the catalog allows it.
- Require `adjacent` mode to return a non-repeated candidate.
- Add CLI thresholds and release-gate enforcement.
- Add tests that prove diversity regressions are observable.

## Non-Goals

- No scoring weight change.
- No new diversity API fields.
- No chatbot implementation.
- No LLM/RAG behavior.
- No map-service, venue, or route-distance implementation.
- No random exploration.

## New Metrics

```text
different_followup_change_rate
different_followup_style_or_category_change_rate
different_followup_missing
different_followup_same_style_or_category
adjacent_followup_change_rate
adjacent_followup_missing
adjacent_followup_same_candidate
```

## Release Gate Thresholds

```text
different_followup_change_rate >= 1.0
different_followup_style_or_category_change_rate >= 0.95
adjacent_followup_change_rate >= 1.0
```

## Acceptance Criteria

- [x] evaluation report includes follow-up diversity metrics.
- [x] CLI can fail on insufficient follow-up diversity.
- [x] release gate enforces diversity thresholds.
- [x] focused checks pass.
- [x] full release gate passes.

## Rollback

Rollback is code/documentation only. Remove the diversity evaluation metrics and
release-gate thresholds. Existing API diversity behavior from Plan 013 remains
unchanged.
