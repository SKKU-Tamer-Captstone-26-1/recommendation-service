# Plan 031 - Beverage Budget Trade-off Explanation Metadata

## Goal

Make beverage recommendation responses more production-ready by returning
deterministic budget trade-off metadata that Flutter and chatbot-service can use
to explain price-sensitive recommendations.

## Problem

Plan 030 proves catalog price signals move beverage scores in the expected
direction. However, app and chatbot surfaces still need display-ready metadata
that explains the budget interpretation without reimplementing scoring logic.

The user-facing problem:

```text
The service recommends a drink that is slightly above the user's stated budget,
but the response does not clearly disclose that the recommendation is a soft
taste-vs-price trade-off based on non-live catalog price observations.
```

## Scope

- Add `budget_tradeoff` metadata to beverage model features.
- Expose the same metadata in beverage recommendation `source_metadata`.
- Include Korean display label and note text.
- Preserve catalog price policy wording: beverage prices are broad catalog
  observations, not live venue offers or inventory truth.
- Add tests for in-budget and above-budget trade-off states.
- Document the response metadata contract.

## Non-Goals

- No scoring weight change.
- No hard budget filtering.
- No venue/menu live price handling.
- No map-service, chatbot, Flutter, or LLM implementation.
- No new database schema.

## Acceptance Criteria

- [x] beverage model features include `budget_tradeoff`.
- [x] beverage recommendation `source_metadata` includes `budget_tradeoff`.
- [x] above-budget recommendations disclose soft taste-vs-price trade-off.
- [x] tests prove the metadata contract.
- [x] focused checks pass.
- [x] full release gate passes.

## Rollback

Rollback is code/documentation only. Remove `budget_tradeoff` from model
features and response source metadata. Existing budget scoring remains
unchanged.
