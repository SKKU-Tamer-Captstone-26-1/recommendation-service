# Plan 021 - Korean Beverage Explanation Templates

## Goal

Make beverage recommendation responses more production-ready for Flutter and
chatbot consumption by replacing English debug-style explanation text with
deterministic Korean explanation templates.

## Problem

Beverage ranking has become more precise through exclusion controls, feedback
suppression, budget-aware scoring, image metadata, and `scoring_v3`
category-aware similarity. However, the explanation text still reads like an
internal debug string:

```text
{name} is recommended because: category match, ...
```

That is not suitable for the mobile UI or for chatbot-service grounded context.
The explanation should be Korean, concise, deterministic, and traceable to
stored reason codes.

## Scope

- Add Korean reason-code text for beverage recommendation reasons.
- Sort reason codes by a stable product-facing priority.
- Generate Korean explanation text from the ranked reason codes.
- Persist the active scoring config's explanation `template_version`.
- Keep score, rank, diversity, feedback, and image behavior unchanged.
- Document the chatbot boundary: LLM may rewrite grounded text, but must not
  invent reasons or change rank.

## Non-Goals

- No recommendation ranking change.
- No scoring weight change.
- No ML training.
- No LLM call.
- No chatbot-service implementation.
- No Flutter implementation.
- No map, venue, inventory, or price ownership change.

## Explanation Contract

For beverage results, `explanation` is generated from:

```text
beverage name
style metadata
reason_codes
matched dimensions
budget feature when relevant
scoring_config.reason_code_rules_json.template_version
```

The response must not mention facts that are not present in structured
recommendation-service data.

## Acceptance Criteria

- [x] beverage explanations are Korean deterministic text.
- [x] reason codes are ordered by stable product-facing priority.
- [x] `RecommendationExplanation.template_version` uses the scoring config
      template version when present.
- [x] API docs show Korean explanation text.
- [x] recommendation logic docs define the explanation boundary.
- [ ] focused tests pass.
- [ ] release gate passes.

## Rollback

Rollback can be done by reverting this plan's code and documentation changes.
The database schema is unchanged. Ranking and scoring configs are unchanged.
