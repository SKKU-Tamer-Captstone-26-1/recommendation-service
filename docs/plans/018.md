# Plan 018 - Active Scoring Evaluation Gate

## Goal

Make the offline drink recommendation evaluation gate validate the same beverage
scoring version used by deployed recommendation traffic.

## Problem

Plan 015 changed the active production scoring config to:

```text
scoring_v2
```

but the local drink evaluation helper still built its synthetic scoring config
from `scoring_v1`. That meant release gate success was useful, but not strong
enough production evidence for the active scorer.

## Scope

- Default offline drink evaluation to `scoring_v2`.
- Allow explicit scoring version selection for regression checks.
- Make the release gate pass `--scoring-config-version scoring_v2`.
- Add tests proving the generated report records `scoring_v2`.

## Non-Goals

- No scoring weight change.
- No new migration.
- No new ML model.
- No fixture threshold relaxation.
- No chatbot or Flutter change.

## Acceptance Criteria

- [x] `evaluate_seed_drink_recommendations` defaults to `scoring_v2`.
- [x] The CLI exposes `--scoring-config-version`.
- [x] `verify-release-gate.sh` explicitly evaluates `scoring_v2`.
- [x] Evaluation tests assert the report scoring version is `scoring_v2`.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

If a scoring-v2 regression is found:

```text
ACTIVE_SCORING_CONFIG=scoring_v1
```

can still roll serving back to `scoring_v1`, and the evaluation CLI can be run
with:

```bash
python3 -m app.tools.evaluate_drink_recommendations \
  --scoring-config-version scoring_v1
```
