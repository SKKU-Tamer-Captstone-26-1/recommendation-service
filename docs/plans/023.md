# Plan 023 - Route Distance Provider Fallback Foundation

## Goal

Prepare selected-beverage venue recommendations for future map-service route
distance integration without making map-service route availability a single
point of failure.

## Problem

Plans 014 and 019 made venue distance route-ready through an injected
`VenueDistanceProvider`. However, a future map-service route adapter may fail to
produce a route estimate for some candidates because of missing route data,
transient API errors, quota limits, or unsupported place types.

If recommendation-service treats every missing route estimate as an invalid
candidate, a partial map-service route failure could erase good store, bar, pub,
or outdoor candidates even when straight-line snapshot coordinates are still
available.

## Scope

- Add `FallbackVenueDistanceProvider`.
- Try a primary route-aware provider first.
- Fall back to `StraightLineVenueDistanceProvider` when the primary provider
  returns no distance feature.
- Preserve per-result distance metadata exactly as the provider returned it.
- Preserve mixed route/straight-line request log metadata.
- Add tests for straight-line fallback and mixed strategy logging.

## Non-Goals

- No real map-service API client yet.
- No direct map-service DB read.
- No route optimization algorithm.
- No Kakao API integration.
- No protobuf change.
- No scoring weight change.
- No Flutter, gateway, or chatbot implementation.

## Future Integration Shape

When map-service exposes a route API:

```text
route_provider = MapServiceRouteDistanceProvider(...)
distance_provider = FallbackVenueDistanceProvider(
  primary=route_provider,
  fallback=StraightLineVenueDistanceProvider()
)
service = BeverageRecommendationService(
  session,
  venue_distance_provider=distance_provider
)
```

The map-service adapter must call approved map-service APIs only. It must never
read map-service databases directly.

## Acceptance Criteria

- [x] route provider fallback class exists.
- [x] missing primary distance uses straight-line fallback.
- [x] mixed route and straight-line results log `mixed_distance_strategy`.
- [x] docs explain fallback behavior and per-result distance interpretation.
- [ ] focused tests pass.
- [ ] full release gate passes.

## Rollback

Rollback is code/documentation only. Remove the fallback provider and tests. The
existing straight-line default provider remains unchanged.
