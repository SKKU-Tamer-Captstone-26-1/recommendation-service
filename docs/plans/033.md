# Plan 033 - Map Route Distance Provider Adapter Base

## Goal

Prepare recommendation-service for future map-service route distance integration
without inventing a map-service proto or reading map-service databases.

## Problem

Venue/store/outdoor recommendations already use `VenueDistanceProvider` and can
fall back to straight-line distance. What is still missing is a small adapter
contract that lets a future map-service client provide route distance estimates
without changing recommendation ranking code.

The user-facing goal remains:

```text
When map-service is ready, recommendation-service can rank venues/stores/outdoor
spots with route-aware distance from the user's lat/lng while preserving
fallback and metadata semantics.
```

## Scope

- Add `MapRouteDistanceClient` protocol.
- Add `MapRouteDistanceProvider` adapter that converts client route estimates
  into validated `VenueDistanceFeature` objects.
- Preserve no-route behavior as `None` so `FallbackVenueDistanceProvider` can
  use straight-line fallback.
- Add tests for route estimate conversion and no-route fallback behavior.
- Document the future map-service client contract.

## Non-Goals

- No map-service proto invention.
- No gRPC/HTTP network client implementation.
- No map-service database reads.
- No scoring weight change.
- No Flutter, chatbot, gateway, or LLM implementation.

## Adapter Contract

```text
MapRouteDistanceClient.route_distance(...)
  input:
    place_id
    origin_lat
    origin_lng
    destination_lat
    destination_lng
    requested_at

  output:
    MapRouteDistanceEstimate | None
```

`None` means the route service could not produce a usable route estimate for
that candidate. It is not an error by itself when a straight-line fallback is
configured.

## Acceptance Criteria

- [x] map-route client protocol exists.
- [x] map-route provider adapter returns route `VenueDistanceFeature`.
- [x] adapter returns `None` when venue coordinates or route estimates are
  missing.
- [x] fallback provider can use straight-line distance after no-route output.
- [x] focused checks pass.
- [x] full release gate passes.

## Rollback

Rollback is code/documentation only. Remove the adapter protocol and tests.
Existing straight-line/fallback provider behavior remains unchanged.
