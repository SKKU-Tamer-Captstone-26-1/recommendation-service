# Plan 035 - Licensed Beverage Direct Display Images

## Goal

Make beverage recommendation cards look more specific in Flutter by adding
license-aware direct display images for selected canonical beverages while
preserving safe category fallback images for the rest.

This is not recommendation scoring work.

## Problem

Plan 017 and Plan 022 made every active beverage displayable by adding category
representative images and release-gated image coverage. That was safe for MVP,
but the app can look repetitive when multiple whiskey, beer, or cocktail
recommendations share the same category image.

Direct product images from random search results, retailer thumbnails, or
official marketing pages are risky because licensing and hotlinking permission
are often unclear. We need a production-safe middle step.

## Scope

- Add source-checked Wikimedia Commons direct image candidates for selected
  canonical beverages.
- Keep source URL, license URL, attribution, review status, and display policy
  in `metadata_json.image`.
- Add an Alembic data migration that backfills existing `beverage_items` rows
  by `metadata_json.source_candidate_id`.
- Preserve category representative fallback images for beverages without a
  direct licensed image.
- Update tests and docs for mixed image kinds.

## Non-Goals

- No binary image files are stored in this repository.
- No official packshot scraping.
- No retailer thumbnail usage.
- No recommendation ranking, scoring, vector, price, inventory, or venue logic
  change.
- No Flutter code change.
- No map/place image ownership change.

## Boundary Decision

Canonical ownership:

```text
recommendation-service owns curated MVP beverage catalog display metadata.
```

This service may store display image metadata for the curated beverage catalog.
Images remain display-only metadata and must not influence recommendation
decisions.

## Image Kinds

Supported MVP image kinds:

```text
category_representative
licensed_product_representative
licensed_cocktail_representative
```

Meanings:

- `category_representative`: safe fallback by beverage category.
- `licensed_product_representative`: direct product/drink image from a reusable
  licensed source page.
- `licensed_cocktail_representative`: direct cocktail image from a reusable
  licensed source page.

## Data Shape

Direct image candidates are stored in:

```text
data/beverage/image_candidates.jsonl
```

Rows with `beverage_candidate_id` override category fallback rows during seed
promotion.

Existing deployed DB rows are backfilled by:

```text
migrations/versions/0008_beverage_direct_display_images.py
```

The migration updates only `beverage_items.metadata_json` and only for active
rows whose `metadata_json.source_candidate_id` matches a selected canonical
candidate.

## Acceptance Criteria

- [x] Direct image candidates exist for selected canonical beverages.
- [x] Remaining active beverages keep category representative fallback images.
- [x] Importer prefers direct image rows over category fallback rows.
- [x] Existing DB rows can be updated through an Alembic migration.
- [x] Image URL coverage remains `1.0`.
- [x] Image license metadata coverage remains `1.0`.
- [x] Image metadata remains display-only and does not affect ranking.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

Rollback path:

```text
alembic downgrade 0007_scoring_v3
```

The downgrade restores the original category representative image metadata for
rows touched by the direct-image migration.
