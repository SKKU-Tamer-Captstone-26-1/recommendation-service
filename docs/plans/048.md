# Plan 048 - Deployed Beverage Recommendation Contract Smoke

## Goal

Strengthen production evidence for drink recommendations by validating that the
deployed `GetBeverageRecommendations` RPC returns Flutter/chatbot-ready beverage
cards, not just a non-empty result count.

## Problem

The deployed recommendation smoke previously confirmed profile status and could
count beverage recommendations. That was useful for reachability, but weak as
production evidence. A deployed service could return results missing display
names, reason codes, explanations, image metadata, or budget trade-off metadata
and the smoke would still pass.

## Scope

- Add opt-in beverage response contract validation to deployed smoke.
- Verify sequential ranks, ids, display names, category, finite score, reason
  codes, explanation, score breakdown metadata, and `metadata.source`.
- Optionally require image metadata for Flutter cards.
- Optionally require budget trade-off metadata for chatbot/Flutter explanation.
- Allow deployed smoke to send `diversity_mode` and `flavor_direction` request
  controls.
- Add focused tests.
- Document the environment variables.

## Non-Goals

- No scoring formula change.
- No DB schema change.
- No API/proto change.
- No Flutter, gateway, chatbot, map-service, or LLM implementation.
- No model training.

## Environment

```text
RECOMMENDATION_SMOKE_RUN_BEVERAGE=true
RECOMMENDATION_SMOKE_EXPECT_BEVERAGE_RESULTS=true
RECOMMENDATION_SMOKE_VALIDATE_BEVERAGE_CONTRACT=true
RECOMMENDATION_SMOKE_REQUIRE_IMAGE_METADATA=true
RECOMMENDATION_SMOKE_REQUIRE_BUDGET_TRADEOFF=true
RECOMMENDATION_SMOKE_DIVERSITY_MODE=ADJACENT
RECOMMENDATION_SMOKE_FLAVOR_DIRECTION=SMOKIER
```

`RECOMMENDATION_SMOKE_VALIDATE_BEVERAGE_CONTRACT` is opt-in so older staging
deployments can still run reachability smoke. Production-like evidence should
enable it.

## Acceptance Criteria

- [x] Deployed smoke can validate beverage card contract.
- [x] Deployed smoke can require image metadata.
- [x] Deployed smoke can require budget trade-off metadata.
- [x] Deployed smoke forwards diversity mode controls.
- [x] Deployed smoke forwards flavor direction controls.
- [x] Missing required display metadata fails the smoke.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

Rollback is code/documentation only. Remove the opt-in validation helpers,
request-control env mapping, tests, and docs. Existing reachability smoke
behavior remains unchanged when validation env vars are unset.
