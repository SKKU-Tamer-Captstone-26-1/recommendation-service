# Plan 046 - Drink Evaluation Margin Release Gate

## Goal

Make offline drink recommendation evidence stricter by requiring reviewed
positive beverages to beat reviewed negative counterexamples by a minimum score
margin, not merely by an infinitesimal amount.

## Problem

Plans 042 and 043 made positive-vs-negative and directional follow-up
preference rates mandatory. That proves directionality, but a barely positive
margin can still pass. In production, tiny margins are fragile because a small
catalog metadata fix, scoring config tweak, or mapper adjustment can flip the
ranking.

## Scope

- Expose minimum and average directional follow-up positive-negative margins.
- Add CLI thresholds for:
  - `minimum_positive_negative_margin`
  - `minimum_directional_followup_margin`
- Tighten the release gate with conservative margins based on current reviewed
  fixture evidence.
- Add focused tests for margin reporting.
- Document the new gate.

## Non-Goals

- No scoring formula change.
- No fixture rewrite.
- No DB schema change.
- No API/proto change.
- No Flutter, chatbot, gateway, map-service, or LLM implementation.

## Thresholds

Current reviewed fixture evidence:

```text
minimum_positive_negative_margin >= 0.15
minimum_directional_followup_margin >= 0.05
```

The directional threshold is intentionally lower because taste-direction
follow-ups such as "smokier" or "less sweet" may be subtle within the same
category. The gate should catch fragile or inverted behavior without forcing
over-aggressive scoring changes.

## Acceptance Criteria

- [x] Evaluation report includes `minimum_directional_followup_margin`.
- [x] Evaluation report includes `average_directional_followup_margin`.
- [x] CLI can fail on weak positive-negative margin.
- [x] CLI can fail on weak directional follow-up margin.
- [x] Release gate requires both margin thresholds.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

Rollback is limited to evaluation reporting, threshold flags, tests, and docs.
Remove the new margin thresholds only if product review accepts weaker offline
recommendation evidence.
