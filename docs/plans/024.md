# Plan 024 - Deployed Survey Mapper Coverage Gate

## Goal

Prevent drink recommendation quality regressions when survey-service changes
category, style, flavor, or budget tokens.

## Problem

The deployed survey-service now returns category-based fields through
`ontheblock.survey.v1.SurveyResult`. Recommendation quality depends on every
survey token mapping deterministically into the derived taste profile. If a new
survey token is added without a mapper update, users can submit valid surveys
that lose preference evidence during profile generation.

## Scope

- Define the deployed survey token contract used by the current adapter.
- Add a survey mapper audit service.
- Add a CLI audit tool.
- Add focused tests proving full coverage and failure detection.
- Add the audit to the local release gate.
- Document the release gate in survey mapping and operations docs.

## Non-Goals

- No survey-service database read.
- No raw survey ownership in recommendation-service.
- No new survey API.
- No mapper weight change.
- No new mapper version.
- No Flutter, gateway, or chatbot implementation.
