# Plan 045 - HTTP Map Route Distance Runtime Client

## Goal

Make the future map-service route distance integration executable from runtime
configuration instead of test-only injection.

The user-facing target remains:

```text
When map-service exposes an approved route distance API, recommendation-service
can score venue/store/outdoor recommendations with route-aware distance from the
user's lat/lng while preserving straight-line fallback metadata.
```

## Problem

Plans 033, 034, and 036 created the provider protocol, fallback behavior, and
request observability. The remaining gap was that the gRPC runtime could not
construct a concrete route client from `MAP_SERVICE_URL` and route-distance
settings. Enabling `MAP_ROUTE_DISTANCE_ENABLED=true` without an injected client
still returned the straight-line provider.

## Scope

- Add a concrete HTTP map-route distance client.
- Add a parser for the route-distance response contract.
- Add optional Cloud Run server-to-server ID token support through the metadata
  server.
- Wire the client into `RecommendationGrpcServicer` when route distance is
  enabled.
- Keep fallback enabled by default.
- Add focused unit tests.
- Document the environment and route-distance contract.

## Non-Goals

- No map-service DB access.
- No map-service canonical schema.
- No route optimization inside recommendation-service.
- No scoring weight change.
- No Flutter, gateway, chatbot, or LLM implementation.
- No committed secrets or service-account keys.

## HTTP Contract

Request:

```http
POST /internal/v1/recommendation/route-distance
```

```json
{
  "contract_version": "map_route_distance_request_v1",
  "place_id": "place_123",
  "origin": {"lat": 37.5, "lng": 127.0},
  "destination": {"lat": 37.501, "lng": 127.001},
  "requested_at": "2026-06-08T12:00:00+00:00"
}
```

Response:

```json
{
  "route_distance_m": 780.4,
  "route_duration_seconds": 520,
  "route_complexity": "simple",
  "confidence": 0.88
}
```

`204` or `404` means no usable route estimate. The provider returns `None`, and
`FallbackVenueDistanceProvider` can use straight-line distance.

## Runtime Contract

```text
MAP_ROUTE_DISTANCE_ENABLED=false
  -> StraightLineVenueDistanceProvider

MAP_ROUTE_DISTANCE_ENABLED=true
  -> HttpMapRouteDistanceClient
  -> MapRouteDistanceProvider
  -> FallbackVenueDistanceProvider(primary=route, fallback=straight-line)
```

If `MAP_SERVICE_SERVERLESS_AUDIENCE` is set, the client fetches a Google ID
token from the Cloud Run metadata server and sends it as:

```text
x-serverless-authorization: Bearer <google-id-token>
```

If token fetch fails, the route client returns no route estimate so fallback can
preserve valid venue candidates.

## Acceptance Criteria

- [x] HTTP route client posts the documented request shape.
- [x] HTTP route client parses route distance, duration, complexity, and
  confidence.
- [x] `204`, `404`, malformed payloads, request errors, and missing serverless
  tokens return no route estimate instead of crashing ranking.
- [x] gRPC runtime constructs a fallback route provider when
  `MAP_ROUTE_DISTANCE_ENABLED=true`.
- [x] No map-service database access is introduced.

## Rollback

Set:

```text
MAP_ROUTE_DISTANCE_ENABLED=false
```

The service returns to straight-line MVP distance without code rollback. Code
rollback is additive: remove the HTTP route client, runtime wiring, and tests.
