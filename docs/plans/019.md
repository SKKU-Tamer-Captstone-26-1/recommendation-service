# Plan 019 - Service-Level Venue Distance Provider Injection

## Goal

Strengthen the base code for future map-service route distance integration by
making venue distance calculation a service-level dependency instead of a hidden
function-level default.

## Problem

Plan 014 introduced a route-ready `VenueDistanceProvider` protocol and
function-level tests, but `BeverageRecommendationService.get_venue_recommendations`
still used the default straight-line provider implicitly. It also wrote
`straight_line_mvp` into request/debug metadata even if a future route-aware
provider supplied route distance facts.

## Scope

- Add `venue_distance_provider` injection to `BeverageRecommendationService`.
- Pass the injected provider into venue ranking/scoring.
- Derive request log distance metadata from actual ranked result source
  snapshots.
- Preserve route-aware metadata in explanation debug JSON.
- Add a service-level test using a fake route provider.

## Non-Goals

- No real map-service API client yet.
- No direct map-service database read.
- No route optimization algorithm inside recommendation-service.
- No Flutter or gateway change.
- No scoring weight change.

## Acceptance Criteria

- [x] Service constructor accepts a venue distance provider.
- [x] `get_venue_recommendations` uses the injected provider.
- [x] Request logs preserve actual `distance_strategy`, `distance_sources`, and
  `is_route_distance`.
- [x] Explanation debug metadata preserves actual route distance strategy.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Future Map-Service Integration

When map-service exposes a route API, implement an adapter with this contract:

```text
VenueDistanceProvider.distance_for(candidate, origin_lat, origin_lng, now)
  -> VenueDistanceFeature(
       strategy="map_route_estimate_v1",
       source="map_service_route_api",
       is_route_distance=true,
       route_distance_m=<provider meters>,
       route_duration_seconds=<provider estimate>
     )
```

The adapter must call map-service APIs only. It must not read map-service
databases directly.
