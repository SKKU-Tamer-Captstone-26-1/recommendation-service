# Plan 028 - Top Recommendation Reason Quality Gate

## Goal

Raise drink recommendation production confidence by requiring the first returned
drink recommendation to carry at least one expected explanation reason code for
each offline evaluation fixture.

## Problem

Plan 027 verifies category, experience-level, and budget-band scenario
coverage. The drink evaluation also reports average reason-code coverage across
the top-k results, but that is not enough for app UX. Flutter and chatbot
surfaces usually explain the first recommendation most prominently.

A release could pass if the expected reason appears somewhere in the top five
while the rank-one recommendation has only generic or unrelated explanation
metadata.

## Scope

- Add per-fixture rank-one reason hit metrics.
- Add aggregate top-result reason hit and coverage metrics.
- Add CLI thresholds for rank-one reason quality.
- Enforce the new thresholds in the local release gate.
- Add tests that prove missing rank-one reason evidence is reported.
- Document the new release gate behavior.

## Non-Goals

- No scoring weight change.
- No reason-code generation change.
- No catalog, survey mapper, or profile mapper change.
- No chatbot, Flutter, map-service, or LLM implementation.

## New Metrics

```text
top_result_reason_hit
top_result_reason_coverage
top_result_missing_reason_codes
top_result_reason_hit_rate
average_top_result_reason_coverage
fixtures_missing_top_result_reason
```

## Release Gate Thresholds

```text
top_result_reason_hit_rate >= 1.0
average_top_result_reason_coverage >= 0.5
```

The first threshold is strict: every fixture must have at least one expected
reason code on the rank-one recommendation. The second threshold prevents the
rank-one explanation from becoming too thin across the full fixture suite.

## Acceptance Criteria

- [x] evaluation report includes rank-one reason quality metrics.
- [x] CLI can fail on insufficient rank-one reason evidence.
- [x] release gate enforces rank-one reason quality.
- [x] focused checks pass.
- [x] full release gate passes.

## Rollback

Rollback is code/documentation only. Remove the rank-one reason metrics and CLI
thresholds from the evaluation report and release gate.
