# Plan 052 - Rank-One Drink Recommendation Evaluation Gate

## Goal

Strengthen drink recommendation quality evidence by requiring the first
returned beverage recommendation to be a fixture-approved positive candidate.

## Problem

The previous drink evaluation gate proved:

- top-k contained at least one approved positive candidate
- approved positives scored above explicit negatives
- reason codes and follow-up behavior passed thresholds

That was strong, but still left a production UI gap. Flutter and chatbot-service
usually present the first recommendation most prominently, so a release could
pass while the first card was not part of the reviewed positive set.

## Scope

- Add `top_result_positive_hit` and `top_result_catalog_key` to fixture results.
- Add aggregate `top_result_positive_hit_rate`.
- Add failure payload `fixtures_missing_top_result_positive`.
- Add CLI threshold `--min-top-result-positive-hit-rate`.
- Require `top_result_positive_hit_rate = 1.0` in the release gate.
- Expand fixture positive sets where previously valid top-ranked catalog
  candidates were not listed as approved positives.
- Update tests and docs.

## Non-Goals

- No scoring formula change.
- No DB schema change.
- No proto change.
- No model training.
- No Flutter, chatbot, gateway, survey, or map-service implementation.

## Acceptance Criteria

- [x] Evaluation report exposes rank-one positive-hit metrics.
- [x] Release gate requires rank-one positive-hit rate to be `1.0`.
- [x] The reviewed fixture set passes with `top_result_positive_hit_rate = 1.0`.
- [x] Threshold helper fails when rank-one positive-hit rate is weak.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

Rollback is evaluation/data/documentation only. Remove rank-one positive metrics
and threshold, then remove the fixture positive label additions if necessary.
