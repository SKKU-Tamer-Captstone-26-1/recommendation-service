# Plan 030 - Beverage Budget Sensitivity Evaluation Gate

## Goal

Make drink recommendations more production-ready by requiring offline evidence
that catalog price signals affect beverage scoring in the expected direction.

## Problem

Plan 027 verifies that evaluation fixtures cover deployed survey budget bands,
but coverage alone does not prove the scoring model responds to budget. A
release could include every budget token while still ranking the same candidates
as if budget did not exist.

The user-facing failure this prevents:

```text
Low-budget user and premium-tolerant user have the same taste profile, but the
price-sensitive part of scoring does not move affordable and premium candidates
in opposite directions.
```

## Scope

- Add budget sensitivity metrics to the drink evaluation report.
- Compare the same fixture taste profile under:
  - `under_30000`
  - `over_200000`
- Require affordable candidates to score higher for the low-budget variant.
- Require premium candidates to score higher for the premium-tolerant variant.
- Add candidate count thresholds so the gate proves the catalog has enough price
  evidence for both sides.
- Add CLI thresholds and release-gate enforcement.
- Add tests for the new budget metrics.

## Non-Goals

- No scoring weight change.
- No strict budget filtering.
- No venue/menu live price handling.
- No map-service, Flutter, chatbot, or LLM implementation.
- No claim that catalog prices are live offers or inventory truth.

## New Metrics

```text
budget_sensitivity_low_budget
budget_sensitivity_high_budget
budget_affordable_candidate_count
budget_premium_candidate_count
budget_affordable_score_preference_rate
budget_premium_score_preference_rate
budget_affordable_score_preference_failures
budget_premium_score_preference_failures
```

## Release Gate Thresholds

```text
budget_affordable_candidate_count >= 20
budget_premium_candidate_count >= 2
budget_affordable_score_preference_rate >= 1.0
budget_premium_score_preference_rate >= 1.0
```

## Acceptance Criteria

- [x] evaluation report includes budget sensitivity metrics.
- [x] CLI can fail on insufficient budget sensitivity.
- [x] release gate enforces budget sensitivity thresholds.
- [x] focused checks pass.
- [x] full release gate passes.

## Rollback

Rollback is code/documentation only. Remove the budget sensitivity metrics and
release-gate thresholds. Existing budget scoring behavior remains unchanged.
