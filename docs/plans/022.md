# Plan 022 - Release-Gated Beverage Display Image Coverage

## Goal

Guarantee that every active beverage recommendation candidate has safe,
traceable display image metadata before deployment.

## Problem

Plan 017 added category representative image metadata and exposed `image_url` to
Flutter. That made images available, but production readiness also needs a hard
release check. Without a gate, a future catalog update could activate a beverage
without an image, Korean alt text, source URL, license, attribution, display
policy, or review status.

## Scope

- Add image metadata validation to the beverage catalog audit.
- Treat missing app-display image metadata as a critical audit failure.
- Add image coverage metrics to audit reports.
- Print image coverage in the CLI audit summary.
- Update tests and docs so the release gate proves image readiness.

## Non-Goals

- No new image search.
- No binary image storage.
- No product-specific bottle image approval workflow.
- No ranking, scoring, vector, or reason-code behavior change.
- No Flutter implementation.
- No map/place image ownership change.

## Acceptance Criteria

- [x] seed beverage catalog audit reports image coverage metrics.
- [x] seed beverage catalog has `image_url_coverage = 1.0`.
- [x] seed beverage catalog has `image_license_metadata_coverage = 1.0`.
- [x] missing display image metadata is a critical audit issue.
- [x] release gate docs include image coverage as deployment evidence.
- [ ] focused tests pass.
- [ ] full release gate passes.

## Rollback

Rollback is code/documentation only. Revert the audit and documentation changes.
The existing image metadata migration and importer behavior remain separate from
this release gate change.
