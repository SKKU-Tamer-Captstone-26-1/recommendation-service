# Plan 040 - Beverage Image Cache Export Tool

## Goal

Prepare beverage display images for an ONTHEBLOCK-managed GCS/Cloud CDN cache
without committing binary assets to this repository.

## Problem

Plan 039 made beverage catalog metadata CDN-ready by adding deterministic
`cache_key`, `original_image_url`, and `BEVERAGE_IMAGE_CDN_BASE_URL` support.
The remaining operational gap is producing a reviewed, traceable export package
for the image cache.

The service should not blindly rely on third-party hotlinking in production,
but the repository also should not store copied image binaries.

## Scope

- Add a service that extracts unique image cache assets from seed records or
  active database beverages.
- Generate an export manifest containing cache key, original image URL,
  source/license/attribution metadata, connected beverage catalog keys, and
  optional GCS URI.
- Add optional download mode that writes binaries to an operator-specified local
  output directory.
- Keep manifest-only mode as the default.
- Add focused tests with fake downloaders.
- Document the GCS/Cloud CDN handoff steps.

## Non-Goals

- No automatic GCS bucket creation.
- No automatic Cloud CDN provisioning.
- No committed image binaries.
- No recommendation scoring changes.
- No DB schema changes.
- No Flutter changes.

## Acceptance Criteria

- [x] Seed export deduplicates shared category fallback images by cache key.
- [x] Export manifest includes original source/license/attribution metadata.
- [x] CDN base URL produces CDN display URLs while preserving original URLs.
- [x] Manifest-only mode writes a report without downloading images.
- [x] Download mode writes image bytes only to the requested output directory.
- [x] Non-image responses are reported as failures.
- [x] Focused tests pass.
- [x] Full release gate passes.

## Rollback

Remove `app.services.beverage_image_cache_export`,
`app.tools.beverage_image_cache_export`, focused tests, and documentation. This
does not affect active recommendation scoring or existing beverage metadata.
